## <font style="color:rgb(51, 51, 51);">Alembic 数据库迁移</font>
<font style="color:rgb(51, 51, 51);">Alembic 是 Python 生态中最主流的数据库迁移（Database Migration）工具。它通过结合 </font>**<font style="color:rgb(51, 51, 51);">SQLAlchemy 的 ORM 元数据（Metadata）</font>**<font style="color:rgb(51, 51, 51);"> 与 </font>**<font style="color:rgb(51, 51, 51);">数据库系统表（</font>**`**<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">alembic_version</font>**`**<font style="color:rgb(51, 51, 51);">）</font>**<font style="color:rgb(51, 51, 51);">，实现了对数据库结构的版本控制与数据持久化管理。</font>

| **<font style="color:rgb(51, 51, 51);">指令</font>** | **<font style="color:rgb(51, 51, 51);">作用说明</font>** |
| :--- | :--- |
| <font style="color:rgb(51, 51, 51);">uv run alembic upgrade head</font> | **<font style="color:rgb(51, 51, 51);">应用最新迁移</font>**<font style="color:rgb(51, 51, 51);">：将所有尚未执行的迁移脚本依序应用到数据库，将数据库结构升级至最新状态。</font> |
| <font style="color:rgb(51, 51, 51);">uv run alembic revision --autogenerate -m '$(MSG)'</font> | **自动生成迁移脚本**：对比 SQLAlchemy ORM 模型与当前数据库表结构的差异，在 alembic/versions/目录下生成附带说明信息 MSG的迁移脚本。 |
| <font style="color:rgb(51, 51, 51);">uv run alembic downgrade -1</font> | **<font style="color:rgb(51, 51, 51);">回滚上一步迁移</font>**<font style="color:rgb(51, 51, 51);">：撤销最近一次应用的迁移脚本，将数据库结构退回到上一个版本。</font> |
| <font style="color:rgb(51, 51, 51);">uv run alembic history --verbose</font> | **<font style="color:rgb(51, 51, 51);">查看详细历史</font>**<font style="color:rgb(51, 51, 51);">：按时间顺序打印出项目中所有的迁移版本日志（包括描述信息等）。</font> |


**<font style="color:rgb(51, 51, 51);">步骤一：定义 SQLModel 模型 (</font>**`**<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">app/models.py</font>**`**<font style="color:rgb(51, 51, 51);">)</font>**

<font style="color:rgb(51, 51, 51);">确保你的模型定义继承自 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">SQLModel</font>`<font style="color:rgb(51, 51, 51);"> 且设置了 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">table=True</font>`<font style="color:rgb(51, 51, 51);">：</font>

```plain
from typing import Optional
from sqlmodel import Field, SQLModel

class User(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    username: str = Field(index=True)
    email: str
    age: Optional[int] = None
```

**<font style="color:rgb(51, 51, 51);">步骤三：配置config.py 文件，指定数据库地址</font>**

```plain
提示：运行后，alembic/versions/ 目录中会生成对应的 Python 迁移脚本（如 1a2b3c4d5e6f_initial_migration_create_users_table.py）。
```

# FastApi接口流程
make dev 本地服务启动后，Swagger 地址为：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

<font style="color:rgb(51, 51, 51);">Token 说明：</font>

| **<font style="color:rgb(51, 51, 51);">Token</font>** | **<font style="color:rgb(51, 51, 51);">获取接口</font>** | **<font style="color:rgb(51, 51, 51);">用途</font>** |
| :--- | :--- | :--- |
| <font style="color:rgb(51, 51, 51);">用户 Token</font> | POST /api/v1/auth/login | <font style="color:rgb(51, 51, 51);">创建和查询聊天会话</font> |
| <font style="color:rgb(51, 51, 51);">Session Token</font> | POST /api/v1/auth/session | <font style="color:rgb(51, 51, 51);">在指定会话中聊天、查询历史、删除该会话</font> |


<font style="color:rgb(51, 51, 51);">每个 Session Token 对应一段独立的聊天记录。Swagger 的 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">Authorize</font>`<font style="color:rgb(51, 51, 51);"> 只能保存一个 Token，因此创建会话后必须将授权 Token 从用户 Token 切换为 Session Token。</font>

# <font style="color:rgb(51, 51, 51);">LLM 服务</font>
## <font style="color:rgb(51, 51, 51);">概览</font>
<font style="color:rgb(51, 51, 51);">LLM 服务（</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">app/services/llm/</font>`<font style="color:rgb(51, 51, 51);">）负责处理所有语言模型调用，提供自动重试、循环模型回退和总超时控制.Agent 代码只需调用 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">llm_service.call(messages)</font>`<font style="color:rgb(51, 51, 51);">，其他逻辑由服务负责.</font>

<font style="color:rgb(51, 51, 51);">该模块拆分为两个文件：</font>

+ `<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">app/services/llm/registry.py</font>`<font style="color:rgb(51, 51, 51);">：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">LLMRegistry</font>`<font style="color:rgb(51, 51, 51);">，定义可用模型</font>
+ `<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">app/services/llm/service.py</font>`<font style="color:rgb(51, 51, 51);">：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">LLMService</font>`<font style="color:rgb(51, 51, 51);">，负责调用逻辑、重试、回退和结构化输出</font>

| **<font style="color:rgb(51, 51, 51);">名称</font>** | **<font style="color:rgb(51, 51, 51);">模型</font>** | **<font style="color:rgb(51, 51, 51);">说明</font>** |
| :--- | :--- | :--- |
| `<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">gpt-5-mini</font>` | <font style="color:rgb(51, 51, 51);">gpt-5-mini</font> | <font style="color:rgb(51, 51, 51);">默认模型，低推理强度</font> |
| `<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">gpt-5.4</font>` | <font style="color:rgb(51, 51, 51);">gpt-5</font> | <font style="color:rgb(51, 51, 51);">中等推理强度</font> |
| `<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">gpt-5.4-nano</font>` | <font style="color:rgb(51, 51, 51);">gpt-5.4-nano</font> | <font style="color:rgb(51, 51, 51);">响应快速，低推理强度</font> |

**<font style="color:rgb(51, 51, 51);">重试配置</font>**<font style="color:rgb(51, 51, 51);">（每个模型独立）：</font>

+ <font style="color:rgb(51, 51, 51);">最大尝试次数：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">MAX_LLM_CALL_RETRIES</font>`<font style="color:rgb(51, 51, 51);">（默认值：3）</font>
+ <font style="color:rgb(51, 51, 51);">等待策略：指数退避，最小 2 秒，最大 10 秒</font>
+ <font style="color:rgb(51, 51, 51);">重试错误：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">RateLimitError</font>`<font style="color:rgb(51, 51, 51);">、</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">APITimeoutError</font>`<font style="color:rgb(51, 51, 51);">、</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">APIError</font>`

**<font style="color:rgb(51, 51, 51);">总超时：</font>**`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">LLM_TOTAL_TIMEOUT</font>`<font style="color:rgb(51, 51, 51);"> 秒（默认值：60 秒）限制整个循环的最大耗时.没有该限制时，最坏情况耗时为“重试次数 × 模型数量 × 最大等待时间”，可能超过 2 分钟.</font>

**<font style="color:rgb(51, 51, 51);">回退顺序：</font>**<font style="color:rgb(51, 51, 51);"> 按 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">LLMRegistry.LLMS</font>`<font style="color:rgb(51, 51, 51);"> 的顺序循环回退.尝试最后一个模型后会回到第一个模型，并在完成一轮循环后停止.</font>

## <font style="color:rgb(51, 51, 51);">工具+结构化输出</font>
<font style="color:rgb(51, 51, 51);">应用启动时会将工具绑定到 LLM：</font>

llm_service.bind_tools(tools)

<font style="color:rgb(51, 51, 51);">回退过程中切换模型时，工具会自动重新绑定到新模型.</font>

<font style="color:rgb(51, 51, 51);">将 Pydantic 模型作为 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">response_format</font>`<font style="color:rgb(51, 51, 51);"> 传入，可以获得经过校验的实例，而不是原始 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">BaseMessage</font>`<font style="color:rgb(51, 51, 51);">：</font>

```plain
from app.schemas.my_schema import MySchema

result: MySchema = await llm_service.call(
    messages,
    model_name="gpt-5.4-nano",   # 可选，省略时使用当前默认模型
    response_format=MySchema,
    temperature=0.2,
)
```

## <font style="color:rgb(51, 51, 51);">缓存层</font>
<font style="color:rgb(51, 51, 51);">记忆搜索结果会被缓存，避免在同一 TTL 窗口内针对相似问题重复查询 pgvector.</font>

+ **<font style="color:rgb(51, 51, 51);">使用 Valkey/Redis：</font>**<font style="color:rgb(51, 51, 51);"> 缓存在多个应用实例之间共享.在 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">.env</font>`<font style="color:rgb(51, 51, 51);"> 中设置 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">VALKEY_HOST</font>`<font style="color:rgb(51, 51, 51);">.</font>
+ **<font style="color:rgb(51, 51, 51);">不使用 Valkey：</font>**<font style="color:rgb(51, 51, 51);"> 回退到内存 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">TTLCache</font>`<font style="color:rgb(51, 51, 51);">，适合单实例运行.</font>

<font style="color:rgb(51, 51, 51);">缓存键：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">memory:{user_id}:{sha256(query)[:16]}</font>`

<font style="color:rgb(51, 51, 51);">TTL：</font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">CACHE_TTL_SECONDS</font>`<font style="color:rgb(51, 51, 51);">（默认值：60 秒）</font>

<font style="color:rgb(51, 51, 51);">只缓存成功且非空的结果，永远不会缓存错误.</font>

## <font style="color:rgb(51, 51, 51);">记忆更新</font>
<font style="color:rgb(51, 51, 51);">LLM 生成响应后，系统通过 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">asyncio.create_task</font>`<font style="color:rgb(51, 51, 51);"> 在</font>**<font style="color:rgb(51, 51, 51);">后台</font>**<font style="color:rgb(51, 51, 51);">更新记忆.这意味着：</font>

+ <font style="color:rgb(51, 51, 51);">响应会立即返回，无需等待 mem0 完成</font>
+ <font style="color:rgb(51, 51, 51);">记忆更新不会阻塞或拖慢聊天响应</font>

## <font style="color:rgb(51, 51, 51);">启动预热</font>
<font style="color:rgb(51, 51, 51);">应用生命周期启动阶段会调用 </font>`<font style="color:rgb(51, 51, 51);background-color:rgb(243, 244, 244);">memory_service.initialize()</font>`<font style="color:rgb(51, 51, 51);">.该调用会建立 pgvector 连接池并执行 mem0 Schema 检查，避免首次用户请求承担约 130 毫秒的冷启动开销.</font>
